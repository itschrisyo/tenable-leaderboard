## Notes on This Example

### Data Attribution
Every metric in this example would cite its source API endpoint in a production run. The agent never fabricates data — if an endpoint fails or returns incomplete results, it's flagged as `[Data Unavailable]`.

### Ownership Resolution
Assets are mapped to owners using this tag hierarchy (most specific wins):
1. `owner:` tags → explicit assignment
2. `team:` tags → team-level ownership
3. `bu:` tags → business unit ownership
4. `department:` tags → departmental ownership

### Interpretation Guidance
The agent provides plain-language interpretation for non-technical executives:
- "Risk is improving" vs. "Risk is increasing"
- What SLA compliance percentage means
- Why specific patterns require policy attention

### Framing Approach
Performance issues are framed as "Needs Support" or "Escalation Recommended" rather than punitive labels. The goal is organizational improvement, not blame assignment.

### Systemic vs. Individual
The "Systemic Risk Signals" section elevates patterns that suggest policy/process issues rather than individual team failures. This helps leadership distinguish between execution gaps and structural problems.
